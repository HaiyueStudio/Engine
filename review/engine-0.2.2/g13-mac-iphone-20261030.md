## 画面对照调查（已解决）

[同候选浏览器与 Native 对照](../../artifacts/engine-0.2.2/g13/mac-iphone-20261030/browser-pixel-diagnostic/pixel-discrepancy.json)使用相同包、素材、932×430 逻辑视口及 DPR 2。浏览器初帧和第 120 帧均有右侧红色矩形和紫色图片，Native 第 120 帧缺失；其余布局图片、文字和 GUI 仍可见。当时因 core 素材没有时间轨道而怀疑绘制错误；后续精确时间对照纠正了这个判断，原记录保留。

第 15 轮（build 18）在 build 17 人工结束且原始记录保存后安装。[430×932 竖屏 GPU 对照](../../artifacts/engine-0.2.2/g13/mac-iphone-20261030/device-round-15/gpu-comparison.json)前 325 条 core 公开 GPU 记录完全相同，覆盖顶点、索引、变换数据采样、着色器、管线与绘制调用；Native 仍缺两个图形。记录上限为三次提交／500 条，每个 buffer 仅采前 320 字节，不能当作完整 GPU 内存读回。该诊断轮次不继承 build 17 人工通过结论。

后续定位：第 16 轮十项独立朝向／剔除测试通过。第 17 轮在资源退休后回读被 GPU 拒绝，返回的零数据明确作废。第 18 轮首帧同步回读了 76 份缓冲，其中 75 份有完整上传记录且逐字节一致（含全部 core 数据）；一份 16 字节 GUI 数据超出原 500 条日志上限，未比对。实际 iPhone 第一帧能够显示矩形和图片，第 120 帧才隐藏。

时间合同复核发现 core 素材声明 `duration: 2`；没有动画轨道不意味着节点永久可见。原执行器在 `time > start + duration` 时隐藏节点。浏览器精确采集 0、1、2、2.001、3 秒，红色矩形像素分别为 34,950、34,950、34,950、0、0。原先浏览器固定 1/60 步长与 iPhone 实际帧间隔的“第 120 帧”比较跨过了不同的生命周期边界，不能用于授予像素失败结论。原始疑似失败保留，不改写记录。第 19 轮持续跟踪构建因新定位而未安装；第 20 轮时间采图器提前暂停、遇到资源待就绪，亦保留为无效诊断，正常启动流程不变。

第 21 轮（build 24）[精确时间对照](../../artifacts/engine-0.2.2/g13/mac-iphone-20261030/device-round-21/timeline-parity-audit.json)使用同一素材和公开 Player 的暂停／seek，等待资源就绪后采集真实表面。iPhone 五个时间点的实际时间均精确匹配，红色像素数与浏览器逐项相同；矩形区域逐像素一致，图片区域通道最大差为 1/255，2 秒后两区域均一致为空。HYA 文字区域有 76 个像素的栅格化差异，最大通道差 142、区域平均绝对通道差约 0.012/255；系统字体 GUI 字形另受宿主字体影响。该记录解决显示／隐藏和 core 图像疑点，不将其宣称为全屏逐像素一致，也未调整正式像素预算。**无需引擎或资源复用修复；本轮所有临时诊断已从标准源码移除。**
