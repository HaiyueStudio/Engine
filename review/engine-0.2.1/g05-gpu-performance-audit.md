# G05 GPU 耗时与完整性能验收审计 — 2026-09-28

> 后续空闲主机续测、冷却脚本修复及当前版本资源/包验收见 [2026-09-28 晚间审计](g05-resume-audit.md)。下文保留此前尝试的原始结论。

## 结论

**验收失败且全量人口未完成，G05 不能收尾。** 当前运行时保持 `6bb2179a2fd27d7893459dd4e52f1d9494d5f440d13ada872a327a04551d9c42`。所有 GPU 优化实验均已撤回；没有扩大预算、降低画质、修改版本或发布。

两个独立问题已分开记录：

1. **性能预算失败：** Intel 高重叠 Tiled 的一次完整采样在前后 CPU speed/scheduler 均为 100 时，GPU P95 为 **62.70 ms**，冻结预算为 **24 ms**。本轮组已经不可能通过：即使其余 600 个尚未测量的 GPU 样本都取理论最优的 0 ms，900 样本池的最近秩 P95 下界仍为 **62.242527 ms**。这是失败证明，不是补齐或替代三轮样本。
2. **主机资格失败：** Intel GTAO reference / tiled 分别在结束时报告 CPU speed limit **75 / 46**。后续 Forward、F、E/G 各门禁均在首例启动前报告 **48 / 53 / 66**，停止采样。没有把这些失败写成通过，也没有把旧轮次拼进新矩阵。

### AO 归因

- AMD GTAO Tiled 整帧 **26.52 ms**，Resolve **4.33 ms**；对应 reference 整帧 **43.21 ms**、Resolve **16.45 ms**。仍需完整三轮后才能给出性能资格或稳定收益结论。
- Intel GTAO Tiled 的限速诊断中，AO 主计算 P95 **84.97 ms**、denoise **21.16 ms**、辅助法线 **18.87 ms**、Resolve **85.84 ms**。整帧为 **220.67 ms**；各阶段 P95 不能简单相加当成整帧 P95。
- 1080p AO 的目标分配仍为 **66,869,272 B**，在 64 MiB 预算内；保留 **433** 个 tile 记录，**7,727** 个 tile 使用完整灯表回退。内存达标不代表性能达标。64 MiB 是 Deferred 目标预算；Intel Tiled 完整采样中，含 AO 内部暂存和场景资源的总分配估算为 **142,839,540 B**，不是驱动实际驻留显存。

## 实现与验证

新增可复用的 24 次专项采样入口 `run-deferred-g05-gpu-focus.mjs --full`，保留固定场景、两个原生 adapter、reference/tiled 配对、三轮顺序、独立 CPU/GPU 人口与 120 秒冷却。新增仅能判定失败或不确定的池化 P95 下界审计；它永远不能给缺失人口判通过。

- **185** 项性能策略测试通过；专项/Shader/灯表聚焦测试 **18** 项通过，下界审计测试 **4** 项通过（与 185 有重叠，不相加）。
- modules（485 个模块）、responsibilities、同步 prepare、API 与 milestones 检查通过。
- 三个 GPU 实验均通过 AMD/Intel 原生像素回归，但未证明所需收益，已恢复原代码与生成产物。详情见 [实验记录](g05-gpu-arithmetic-experiments.md)。
- 本次没有新增产品运行时代码；原 6bb 版本此前的 typecheck、1380 项根测试、95 个新鲜构建目标记录继续保留在 [CPU 缓存检查点](g05-light-cache-checkpoint.json)。这些结构/构建结果不替代性能人口。

专项入口审计时补齐了算法顺序交错：反转两个 workload 不再抵消 reference/tiled 的逐轮交替。实际采到的第 0 轮顺序不变；原失败计划及其全部策略源文件已另行归档，后续仍需从头执行新的完整计划。
