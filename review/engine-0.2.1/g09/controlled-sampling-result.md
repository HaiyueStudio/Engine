## 针对性优化

`Render3DFramePlan` 和 `PostProcessGraph` 原来即使命中结构缓存，也每帧创建嵌套数组并完整 JSON 序列化。现在逐字段核对完整结构；结构不变时复用原完整序列化键，仍查询原有有界缓存，继续处理设备代际、禁用开关和 LRU。变化时使用原序列化形式生成新键，不引入短哈希或结构碰撞。保存的仅为复制的字符串和布尔值，当前帧回调、效果实例、动态需求和物理资源继续实时绑定。

结构检查覆盖 imports/exports 的内容和顺序、全部节点及 reads/writes/after、副作用、scope、设备切换、效果替换与动态辅助需求。自定义需求读取抛错时，会使待复用的序列化键失效，防止下次编译沿用部分更新前的旧键。稳定帧 200 次重复执行的键序列化由 200 次降至 0 次；这是结构工作量的验证。

首次 Node 微基准中，16 节点计划及四效果图的 P50 均下降，8 节点计划有一轮变慢；该结果保存在 `microbenchmark-before-exception-guard.json`。补齐上述异常恢复分支后，按同样三轮交错方案核验最终源码：8 节点 P50 从 0.00790–0.00804 ms 降为 0.00558–0.00584 ms，16 节点从 0.01426–0.01451 ms 降为 0.01043–0.01081 ms，四效果图从 0.00133–0.00163 ms 降为 0.00052–0.00057 ms。[最终原始微基准](../../../artifacts/engine-0.2.1/g09/record-key-optimization-20261007/microbenchmark.json)绑定源码哈希，保留全部批次。在线微基准不能替代浏览器整帧验收，也不能据此宣称两个 CPU 回归已修复。
