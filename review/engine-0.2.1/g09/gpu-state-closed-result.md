## 结论与边界

计时窗口内的连续观测确认：相同八灯 A0 工作负载，在不同轮次进入了不同的 GPU P-state、核心频率和显存频率，对应约三倍的耗时差。延长到完整 2400 帧没有让这些状态趋同。当前主要验收障碍是跨轮 GPU 状态不可比，不能靠删除快轮、继续延长预热或扩大预算解决。

本轮并非合格的独立安静采样：EpicGamesLauncher（PID 9376）和两个 EpicWebHelper（9868、15312）出现在全部 288 次进程观测中，因此原始 [completion.json](../../../artifacts/engine-0.2.1/g09/gpu-state-closed-20261009T013726Z/completion.json) 保留 `failed`。捕获本身均成功，失败来自采后后台进程检查。离线分析只补齐被原启动器提前中断的后五份分析，不改写原完成状态，不提升为性能资格。

第 5 次的八个固定 300 帧窗口均处于 P0 / 1607 / 4006，P95 为 0.288768–0.292864 ms；第 4 次的八个窗口均为 P8 / 544 / 405，P95 为 1.004544–1.016864 ms。因此此前快轮并非只有结束快照偶然显示了较高频率。

大多数轮次在浏览器启动后先进入 P0，再依次降到 P2/P5/P8，在 GPU 测量前已经处于低状态；第 5 次在测量约 20.8 秒前回到 P0，并维持整个 GPU 测量段。这表明固定 CPU 预热帧数并不等于固定 GPU 电源状态。GPU 测量阶段温度 49–55°C，记录到的三个温度/供电降速标志均为 Not Active；这不是对所有降速机制的排除证明。

还存在未被频率差解释的局部波动：第 1 次第 1500–1799 帧窗口的 P95 为 1.262560 ms，彼时观测频率仍为 P8 / 594 / 405。该窗口保留，不能声称 GPU 电源策略解决了所有噪声。遥测为约 200 ms 的窗口级证据，不能代替每次 draw 的精确频率观测。

Epic 大部分观测的 CPU 增量为 0，第 2 次捕获有一次约 11.94% 主机 CPU 占用；快的第 5 次没有相应 Epic CPU 增量。仅凭进程存在或其 CPU 值，不能确定 Epic 就是 GPU 状态切换的触发者，也不能证明它没有 GPU 影响。Steam 和任务管理器也在本轮后台进程记录中。

## 后续修复路径与当前阻碍

启动器已加入采样前及轮间后台进程检查；检测到 Codex、VS Code、Epic、Steam 或任务管理器时提前列出名称和 PID，不终止应用。`-PreflightOnly` 可在 Codex 在线时只读检查其他后台，尚未改变任何电源设置。精确进程匹配、空输入、在线只读例外及 Windows PowerShell 5.1 语法检查均通过。采后即使发现后台干扰，也会继续分析所有已捕获的数据，再返回失败，避免遗漏证据。

GPU 的下一步是验证浏览器专属电源策略，先取得可恢复的短对照，再决定是否修订共同条件。NVIDIA 官方 [控制面板说明](https://www.nvidia.com/content/Control-Panel-Help/vLatest/en-us/mergedProjects/nv3d/Manage_3D_Settings_%28reference%29.htm) 提供 Prefer maximum performance；它不是精确锁频，仍需实测状态稳定性。[nvidia-smi 文档](https://docs.nvidia.com/deploy/nvidia-smi/index.html) 将 `--lock-gpu-clocks` 的支持范围列为 Volta 及以后，不能直接将其作为本机 GTX 1070 Ti 的控制方案。

已用 [公开 NVAPI DRS 接口](https://docs.nvidia.com/nvapi/group__drsapi.html) 实现仅针对已有 Google Chrome 单应用配置的实验控制器。设置前保存原始是否存在/继承位置/用户值，异常路径重新读取原设置；不写全局配置，不新建应用配置，不恢复整个驱动数据库。

**此控制器尚未就绪，未接入用户采样入口。** 本机管理员环境下，PowerShell 7 和独立 Windows PowerShell 5.1 都在 SaveSettings 返回 `NVAPI_ERROR (-1)`。两次失败后的新会话回读均与原始状态完全一致：Chrome 没有显式的该项设置。没有留下新的电源设置。此错误是驱动接口的通用保存错误，尚不能归结为权限、数据库损坏或硬件不支持；不据此删除驱动数据库、更改 ACL、重装或升级驱动。

需先确认 NVIDIA 控制面板是否能正常保存并恢复 Chrome 的该项设置。成功后再验证短对照、冻结共同 GPU 条件并重建同机基线；仍沿用 5% 回归和 20%/10% 稳定性门槛。本轮未启动新的长采样，也没有新的验收通过结论。
