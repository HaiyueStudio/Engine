## 为什么还需要六轮独立对照

在线短工程测试中，GPU 测量窗口已能处于 P0，显存为 4006 MHz，但核心频率仍有变化。因此“优先最高性能”仅是应用策略，不能当作频率锁定或稳态已证明。短测时 Codex 与现有浏览器仍开着，仅用于验证采集、清理和恢复，不用于生成性能结论。

独立诊断固定 ABBAAB 六次八灯捕获；每次 CPU 预热 6000 帧、测量 3000 帧，GPU 预热 120 帧、测量 2400 帧，按 8 个固定的 300 帧窗口分析。保留所有样本、所有窗口和失败结果，不自动重试、不挑选速度相近的轮次。200 ms 遥测用于窗口级关联，不声称每一帧都锁定在相同频率。

CPU 条件沿用已验证的临时 AC 最低/最高 100%；GPU 仅临时修改现有 Google Chrome 单应用条目，每轮前后回读，结束或失败都恢复。驱动固定 582.78，不能混入旧 560.94 的基线。服务保持原状态。

## 启动等待修正

用户首次运行被 Taskmgr.exe PID 8088 的前置检查挡住；没有创建独立采样目录，没有应用 CPU/GPU 临时设置。复核时任务管理器已退出，原 AC 最低 5% / 最高 100% 与 Chrome 无显式电源覆盖均保持不变。

旧入口只等待 Codex 退出，随后立即要求其他程序全部关闭；这使关闭程序的先后顺序容易触发失败。新入口在同一个 5 分钟窗口等待所有指定程序，并在名单变化时提示剩余程序；超时给出简明原因和“未开始采样、未改设置”的说明。采样开始后的后台限制仍保留，完整六轮人口、预热、阈值和恢复逻辑不变。

新增 [启动等待检查索引](gpu-start-wait-checks.json)记录 Windows PowerShell 5.1 下的九项检查，包括 Codex 先退出但任务管理器仍在、浏览器依次退出、超时、观察失败以及采样/恢复代码未变化。实际主机的一秒只读等待也验证为超时退出、设置不变；没有启动正式或诊断采样。此前原生与短测检查索引保留为其对应启动器版本的历史证据。

## 独立运行入口

右键以管理员身份运行：

[新 GPU 电源对照入口](../../../artifacts/engine-0.2.1/g09/start-gpu-power-with-codex-closed.cmd)

然后完全退出 Codex、Chrome/Edge，以及 VS Code、Epic、Steam、任务管理器，并保持电脑空闲。入口最多等待 5 分钟，让上述所有指定程序退出；程序退出顺序不影响启动。等待时显示仍在运行的程序，全部关闭后自动开始。超时则在改变设置和开始采样前退出，不强制关闭用户程序。Chrome/Edge 的后台进程也需退出。启动器使用系统 Windows PowerShell 的完整路径，已实际验证 CMD 入口，不依赖 pwsh.exe 的 PATH。

采样通常约 6–8 分钟。完成时应显示 Diagnostic status: diagnostic-complete，CPU 和 Chrome GPU 恢复均为 True，退出码 0。这个状态表示捕获、后台条件与恢复检查完成，GPU 稳态结论还需分析各轮固定窗口。输出保存在 artifacts/engine-0.2.1/g09/gpu-power-closed-*；失败也保留原始文件和恢复日志。

本轮只增加诊断入口和评审记录。正式采样合同、引擎实现及门禁阈值未改；必须先确定可重复的共同 GPU 冷启动／稳态条件，再冻结条件并重建同机新基线，随后完成原完整性能人口和 G05 最终资格。
