# G09 验收异常追查

日期：2026-10-02。状态：**尚未解决，不授予正确性、性能或发布资格**。本轮修改诊断和失败证据保留；没有修改 Engine 运行时、生成 shader、A0 基线、预算或版本。

## 已确认的现象

在最终输出的 clear 中写入 RGBA `[1, 0, 1, 0]`，区分未覆盖区域和 shader 写出的透明黑。保持 alpha 为零，因此原有 4096 像素完整覆盖断言不变。输入 HDR 在帧提交后单独读取；本场景仅一个视图，没有后续视图覆盖该输入。

`black-frame-2026-10-02T13-12-35.030Z/low-power-1-2-B4.json` 中：

- 64×64 输出仅首像素有覆盖，其余 **4095 像素保持诊断底色**。
- compute 读回与独立 texture-to-buffer 直接拷贝一致，最大误差 `1.110282599192658e-8`。
- 最终 pass 的源/目标元数据、viewport、scissor 均为 64×64，记录了 `draw(3)`。
- 输入 HDR 的读回也只剩一个有 RGB 的像素；其余像素有 alpha，但 RGB 为零。不能只修改最终输出而假设上游画面正确。

这排除了仅中心像素抽样造成的误判，并说明两条读回路径都观察到了缺失覆盖的图样。**不能仅凭一致性就证明真实目标内容必然未被绘制**：后续对照证实读回本身也会间歇异常，仍须排除它们共享的底层执行或数据传输问题。它不能证明 Chromium、Dawn、Metal 或硬件中的具体根因。同组旧 A0 也失败，因此不能将所有异常归因于新增 FrameGraph 复用或缓存。

### 同一纹理读回矛盾与全零执行标记

`13-51-15.459Z/low-power-1-1-B4.json` 的 compute 结果覆盖 4096 像素、RGB 最大值约 0.15294，与正常对照一致；紧接着直接拷贝只返回一个黑色不透明像素，其余透明。两次读回之间没有渲染或修改该纹理，最大差异为 1。之后的两个执行标记都正确返回 `[4660, 64, 64, 22136]`。这确认**至少一个读回路径不可靠**；不能选择正常路径将该条目改判为通过。

紧接着 `low-power-1-2-B4.json` 的输出 compute、直接拷贝、HDR 读回和 8 个执行标记字均为零，没有 WebGPU 验证错误。标记缓冲创建时已初始化为 `0xffffffff`，有效执行应改写为固定常量和尺寸；全零不符合任一路径的期望。这条目必须视为执行/读回诊断失败，不能单凭图像零值判断 FrameGraph 输出真的全黑。有效标记也不保证此前其他命令正确执行。

## 诊断改动

- 黑帧诊断保留最终输出底色、输入 HDR、纹理尺寸和各 pass 的 viewport/scissor 记录；可选择 `--coverage=after-pipeline` 重放未能解决问题的顺序假设。该选项仅影响诊断，不改变 A0 文件或生产运行时。
- 增加独立 GPU 执行/纹理尺寸标记。标记失败时，即使主图像看起来正常也必须失败；标记成功也不能替代主图像失败，或证明此前读回一定执行正确。
- 缓存验收失败保留整幅像素、尺寸、alpha 覆盖、缓存命中、附件操作、资源池数据和之前通过的案例。
- 原生小程序新增 `lazy-depth` / `initialized-depth` 对照，使用同一 shader 和同一输出期望，仅改变回退深度纹理初始化。
- 黑帧诊断的 `--coverage=arithmetic-chain` 只替换 GPU 模块创建时的 6 个顶点阶段，记录替换名称和字节数，校验实际替换人口。绑定与完整 fragment 代码由单测确认不变；A0 文件和生产生成文件均未编辑。
- 诊断结束时也重新校验 wrapper 哈希，避免执行中修改入口后误收证据。
- 共享 Chrome runner 在超时/异常时保留最后进度、浏览器版本、控制台异常、进程退出信息及最后 64 KiB stderr，同时写入结构化字段与原有 gate 持久化的 Error.stack。截断 stderr 时明确标记。两个单测和一次有意超时的真实浏览器夹具验证了错误保留；未增加超时上限或自动重试。

`g09/black-frame-2026-10-02T13-35-16.076Z` 是执行标记初版的**诊断框架失败**：在已结束的统计帧之后额外 `writeBuffer`，导致上传分类数与聚合帧数不一致。不能把这些条目当作 Engine 黑帧。后续改为缓冲创建时映射初始化，并保留诊断失败的原始像素。

`g09/black-frame-2026-10-02T13-38-42.907Z` 同样是**诊断框架失败**：标记 shader 使用了 WGSL 保留字 `target`；原生验证错误明确记录了编译失败。这不是 GPU 执行标记的有效实验。更正名称后增加显式编译信息检查，先通过独显单次开发冒烟，GPU 返回两个 `[4660, 64, 64, 22136]`，且无验证错误，再执行完整人口。开发冒烟仅验证夹具，不充当验收。
