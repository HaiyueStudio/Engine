## 原因边界

八灯 B4 第一轮结束频率 531 MHz，第二轮 569 MHz，第三轮 1607 MHz。第三轮所有 300 个 GPU 样本都落在 0.234496–0.294912 ms，六个固定 50 帧子窗口均明显较快，说明不是单个异常值拉低统计。它与此前 P8/P0 状态差异的诊断相符，表明 Chrome“优先最高性能”偏好未能建立可重复的运行频率。

第一轮还有独立的高尾问题：前三个 50 帧子窗口 P95 约 1.37–1.41 ms，后三个约 0.93–1.03 ms。本次没有测量阶段内的连续 P-state/显存时钟或逐 pass 记录，不能断言这部分也是频率造成，亦不能据此认定引擎回归。捕获边界没有热降频标记；这不等于全程排除了降频。观察到的后台 CPU 记录没有直接归因到该高尾。

[先前六轮短诊断](gpu-power-closed-result.md)使用 6000 帧 CPU 预热与 15 秒间隔；本次是 18000 帧与 120 秒。其短时稳定结论不能外推到约 93 分钟的完整运行。当前基准每帧等待 GPU 队列完成，GPU 计时阶段还同步读回 timestamp；这一执行节奏可能影响驱动状态，是待验证的采样机制假设，尚未改动正式工作负载或口径。
