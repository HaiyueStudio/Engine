# G09 单灯连续 GPU 状态诊断

2026-10-12。用户授权补双方一致的单灯连续 GPU 状态诊断，再重建基线。本轮先补足 [v5 独立校准失败](gpu-warmup-calibration-v5-result.md)中缺失的执行期间 GPU 状态证据，保留原失败、三轮人口和 **5% 回归预算**。

## 固定对照与证据边界

- 协议 `g09-single-light-gpu-state-v1`，只定位单灯问题，不缩减最终两场景基线合同。A0 固定历史构建，B4 当前绑定构建；完整诊断按 A0/B4、B4/A0、A0/B4 三轮，共六次。
- 双方保留 v5 单灯场景、既有后处理、720p、24000 CPU 帧（120 + 23880）、10200 GPU 帧（120 + 10080）、B8 八帧上限、16 KiB 读回环、每帧一次提交和原引擎回收通知。每次至少冷却 120 秒，再取得三次 CPU ≤5% 的观察。
- 唯一新增的共同诊断干预是持久 NVIDIA 状态观察进程，每 200 ms 查询 GPU UUID、名称、驱动、P-state、核心/显存频率、温度、GPU/显存利用率、功耗及三类降频原因。双方从浏览器启动前开始记录，直到捕获完成后停止；设置仍由同一 CPU/Chrome GPU/Search 控制器临时设置并恢复。
- 观察器也可能影响低负载状态，因此这批数据仅用于诊断，不能直接授予性能资格或生成新基线。即使六轮全部接近，也不能证明无观察器的原条件已经修复；不按频率归一化耗时，不删除慢轮或自动重试。
- 按帧提交/完成的主机时间边界，报告预热 120 帧、随后各 300 帧及末尾 180 帧，全部保留。每窗列出 GPU 总和、跨度、三个绘制阶段、CPU/等待及相邻 GPU 状态观察。采集前后必须有观察包围 GPU 阶段，最大相邻观察间隔 ≤1000 ms；时间倒退、混入设备、缺少时钟、观察提前退出或读回损坏均报错。
- 200 ms 是离散观察，不是每个 GPU 指令的实时频率。主机收到查询输出的时间也不等于 GPU 时间戳；保留窗口内观察数、前后包围距离、间隔和原始行，不宣称逐帧精确归因。功耗不支持时保留 unavailable，不能填零。

## 后续基线

先比较单灯慢轮是否伴随整个 GPU 阶段的核心/显存频率或 P-state 差异，并检查 CPU、等待、外部进程和温度/降频记录。如果本轮没有复现，只报告未复现及观察器可能的影响；如果观察不足以解释，再决定双方一致的调度事件诊断。确定共同干预后，才冻结新条件并重新做两场景共同校准；通过后自动采全新三轮基线，原 5% 回归预算不变。
