# 固定在途帧上限的批量完成诊断

2026-10-10：工程验证完成，独立全量对照待运行。A0 与 B4 均已通过原生 GPU 短采样、末尾单帧批次、时间戳归属和资源清理检查。尚不能认定主绘制慢段已修复；不生成新基线，原 5% 回归预算及稳定性门槛保持。[复核记录](batch-completion-checks.json)。

## 共同条件与唯一干预

[上一轮完整矩阵](main-pass-full-result.md)中，取消显式等待但逐帧读回会把等待移到读回；每八帧读回但仍逐帧等待也没有双方一致的改善。本轮直接检验取消采样器逐帧等待、按批确认完成的行为。

| 条件 | S8 对照 | B8 批量完成 |
| --- | --- | --- |
| 每帧 GPU 提交 | 1 次 | 1 次 |
| 引擎资源回收完成通知 | 保留，每帧 1 次 | 保留，每帧 1 次 |
| 采样器每帧显式等待 | 保留 | 取消 |
| 时间戳 resolve/copy | 每帧执行 | 每帧执行 |
| 每批完成与读回 | 每 8 帧共同 fence 后映射 | 每 8 帧共同 fence 后映射 |
| 读回资源 | 8 槽，共 16384 字节 | 8 槽，共 16384 字节 |
| 未确认完成帧数上限 | 8；实际保守计数峰值 1 | 8；实际保守计数峰值 8 |

“在途”计数是已提交、尚未经采样器确认完成的保守上界，不是对 GPU 实际同时执行帧数的观测。第 9 帧必须等待前一批 fence、读回、解码及 unmap 全部结束。预热和测量分开收尾，最后不足 8 帧仍会提交完整时间戳结果，不会丢弃尾帧。

双方都增加相同的批次完成 fence，以取得可比较的完成观测时刻。因此历史 R1 不能直接充当本轮 S8 对照。运行时长、实际并发和频率可以随等待方式改变，是此次干预的可能结果，不能被宣称为同时固定。

此实现位于本机诊断目录，未替换生产渲染路径、正式基线或验收采样器。

## 独立全量采样

入口：[start-gpu-batch-completion-safe.cmd](../../../artifacts/engine-0.2.1/g09/start-gpu-batch-completion-safe.cmd)。右键以管理员身份运行；收到“后台诊断已准备好”提示后点确定，退出 Codex 及所列后台应用，保持桌面空闲、不锁屏。预计 40–60 分钟或更长，以最终完成/失败通知为准；启动窗口消失不代表完成，不要重复运行。入口使用系统自带 Windows PowerShell，不依赖 PATH 中的 `pwsh.exe`。

固定顺序如下，第二轮反向：

1. A0/S8、B4/B8、A0/B8、B4/S8。
2. B4/S8、A0/B8、B4/B8、A0/S8。

每次共同 CPU 预热 18000 帧、CPU 测量 3000 帧、GPU 预热 120 帧、GPU 测量 15000 帧；合计 8 次捕获、120000 个 GPU 测量帧。间隔 120 秒冷却并通过主机安静检查；保留相同浏览器参数、200 ms GPU 状态采样、进程观察与 GPU.Light 调度记录。CPU 最低状态 100% 和 Chrome 专属电源偏好只在采样期间共同应用，最后自动恢复。电源偏好不等于锁频。

完整设置见[冻结的诊断计划](../../../artifacts/engine-0.2.1/g09/batch-completion-experiment-plan.json)。不自动重试，不删除异常帧，不用在线短测替换独立样本。

## 结果判读边界

B8 的 CPU 函数返回时刻不能代表 GPU 已完成。双方频率及调度关联统一采用“该批首帧提交至批 fence 完成观测”的保守时间区间；该区间出现外部 GPU 包只能归到整批，不能断言属于其中某一帧。所有原始 GPU 时间戳及顺序保留；短区间没有频率采样点时标记未能观测，不据此编造频率。

先确认 S8 是否复现主绘制慢段，再查看 B8 是否在双方、两轮中一致改变慢段、等待位置和频率分布。每份结果同时保留实际运行时长：固定 15000 帧的 B8 可能明显更短，少见到周期性慢段并不足以证明稳定性修复。如果时长不足或对照未复现，应报告证据不足，另行设计等时长反证，不能临时扩样或放宽正式预算。

本轮工程结果只证明批量完成机制可执行且有界。完整 G09 性能资格、新基线和后续发布工作仍取决于独立结果及原合同门禁。
