# G09：问题、方法、结论

当前候选与资格入口统一见[0.2.1结论](../README.md)和[机读清单](../release-candidate.json)。本页描述方法与有边界的历史结论，不再维护逐次候选/补采时间线。

| 问题 | 方法 | 结论与边界 |
| --- | --- | --- |
| 帧计划重复与无用 pass | 从输出/副作用回溯真实依赖，裁剪活跃根；结构缓存有界，每帧重绑当前资源 | 设备/视图/owner变化使缓存失效；像素与副作用不能因裁剪丢失 |
| 四视图临时纹理重复分配 | 在兼容生存期内复用物理目标，按真实物理资源记账 | 旧配对消融的MRT分配估算24.61→6.15MiB、降低75%，像素一致；不等于总显存或FPS提高75% |
| pending纹理和诊断引用延后释放 | 在GPU完成后退役，清理运动向量、镜面、输出绑定组及owner元数据 | 原资源长跑验证通过，借用纹理所有权不变；当前候选仍需完整生命周期证据 |
| 冷启动首段停顿 | 两次真实提交/GPU完成后进入交互；所有等待计入加载，随后正常engine调度 | 旧36次生产捕获通过登记预算；只是旧源码/主机结果，不证明所有设备或新运行时合格 |
| 低负载频率与提交/等待让微基准波动 | 同版本对照，分开CPU、真实GPU、queue wait、readback；生产采样不逐帧fence/readback | 具体频率/驱动/JIT归因未全部确认；不扣除噪声额度、不挑更快诊断替换正式样本 |
| Intel Gen9空画面/GPU重置 | 保留A0/B4复现，按原生硬件范围单列 | 未证明修复；属于扩展兼容，不冒充独显原生发布资格 |
| 无人值守被后台应用、焦点或收尾打断 | 独立入口分别检查管理员、后台应用、可见性与自有进程退出；临时设置验证恢复 | 持续失焦/隐藏仍失败，不抢焦点、不拼接样本、不终止无关应用 |

方法由 [FrameGraph合同](../../../config/framegraph-acceptance-021.json)、[生产口径](../../../config/framegraph-production-021.json)、[ADR 0124](../../../docs/for-ai/adr/0124-g09-production-performance-acceptance.md)约束。Forward CPU相对5%仅为具名调查，GPU5%、其他预算、画质与资源要求保持。

旧七组数据、全部失败与最初 [A0身份](dependency-baseline.json)继续保留；旧结果只对应原采样/验收提交，不覆盖包含Toast的新运行时。原文、逐轮数字和路径见[校验归档](../../archive/engine-review-process-20261020.json)。当前资格校验仍重读qualification绑定的完整原报告、样本与构建哈希，文档归档不更改门禁输入。
