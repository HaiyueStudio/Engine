## 问题与解决方法

| 问题 | 结论 | 解决方法与边界 |
| --- | --- | --- |
| 帧计划重复工作 | 已接入真实依赖、活跃根裁剪与有界结构缓存 | 从输出和副作用回溯，每帧重绑当前资源；设备、视图变化及 owner 销毁使相关缓存失效 |
| 四视图临时纹理重复分配 | 两浏览器完整消融确认 MRT 物理分配估算 24.61→6.15 MiB，降低 75%，显示像素一致 | 兼容生命周期内复用；收益限于该纹理池，不等于整体显存驻留或 FPS 提升 |
| pending 纹理与诊断引用生命周期 | 修复混合尺寸描边提前销毁，以及运动向量、镜面、输出绑定组和 owner 元数据保留 | 按 GPU 完成时点退休；不改变借用纹理所有权。四项各 310 秒资源长跑通过，最终残留为零 |
| 冷启动前几帧停顿 | 加载阶段完成两次真实提交及 GPU 完成等待后，36 次生产捕获的首段交互均通过 | 等待完整计入加载时间；交互首个 10 秒与随后 30 秒稳态分别验收，OS／驱动缓存不清空 |
| Intel Gen9 空画面或 GPU 重置 | 旧 A0 和 B4 均复现，未证明已修复 | 按 ADR 0117 作为非阻塞扩展兼容；本机结论仅覆盖登记的独显原生路径 |
| CPU 微基准对机器状态敏感 | 48 次诊断的 16 对同版本中，12 对 CPU P95 差异超过 5%，最大 +40.8%；具体频率、驱动或 JIT 归因未定 | Forward 原 CPU 失败保留为调查项；GPU 5%、其他预算、生产流畅度与资源门禁保持。不从结果扣除噪声，不用更快诊断替换正式样本 |
| 低负载 GPU 与提交等待变化 | 旧受控诊断提示批量完成方式影响慢段，但不能推广为全部负载已修复 | 当前生产采用正常调度、不逐帧 fence/readback；消融分列 CPU、GPU、等待、读回和结构收益，不宣称不可靠的微基准同比提速 |
| 独立采样被桌面干扰 | 已区分管理员权限、后台应用、页面可见性及收尾失败；最新完整补采未被中断 | 退出宿主后独立执行，临时停用非密码屏保并验证恢复；持续失焦或隐藏仍失败，不自动抢回焦点或拼接样本 |

## 当前生产与资源证据

2026-10-15，在 i7-7700、GTX 1070 Ti、Windows 10 19045、60 Hz 屏幕上，Chrome／Edge 各两轮完成九场景共 **36 次生产捕获**。覆盖默认 Forward、128 灯 Reference、256 灯 Tiled、1080p GTAO、透明 TAA／模糊、四视图、RTT、镜面与 512 灯压力场景。正常 `engine.run()`、动态相机和完整灯表保持，第二轮反转场景及浏览器顺序。

- **64,806 个稳态间隔**全部满足登记预算；最差 P95 **16.86 ms**、P99 **16.92 ms**，最长 **18.15 ms**，无超过 50 ms 的间隔。
- 首段交互最长 **17.32 ms**，无超过 50 ms 的间隔；加载到就绪 **0.776–1.351 秒**，加载帧全部保留。
- 原预算 P95 20 ms、P99 34 ms、长帧比例 1%、最多连续两帧保持；没有因本次规则调整改变这些值。
- Chrome／Edge × TAA／镜面四项各 **310 秒资源长跑**通过；资源数量、估算字节、owner、缓存和 pending 清理满足原合同。
- F0–F8 **224 次正确性捕获**及 **72 组像素配对**独立复核通过；**40 次 A/B1/B2/B3/B4 消融**完整通过。两浏览器均确认四视图 MRT 分配节省 **18.46 MiB（75%）**，不据此声称整体帧率提升。

测量的是可见生产渲染的 rAF 节奏，以截图、灯光覆盖、错误、可见性和焦点记录核验；不是物理扫描输出时间。CPU 更新到提交与 GPU duration 分列。512 灯属于压力包络，四视图总分辨率为 1280×720；不覆盖所有游戏、移动端或四张完整 720p 视图。
