# M02 Windows reconstruction audit

## Scope

This audit records the state recovered after the repository was copied from the
previous macOS development machine to Windows without its original Git history
or generated `artifacts/` directory. It is a reconstruction report, not formal
release evidence and not a replacement for any CPU, GPU, pixel, screenshot,
fidelity, performance, or release-candidate baseline.

- Source revision inspected: `e9ddeb7962624ccb86cfc6ad263b0ad72f21419b`
- Host used for reconstruction: Windows x64, Node.js `v24.19.0`, npm `11.17.0`
- Audit date: 2026-08-15
- Historical G07 decision revision: `ccb6614684f9fac080bd3f80aa4bb37bf10a05cd`
- Historical decision: NO-GO

The historical decision revision is not reachable in this checkout and its
generated artifacts are absent. The old G07 report is retained only as history;
none of its pass results or measurements are current-revision evidence.

## Source and dependency blockers resolved after reconstruction

The four blockers found by the first audit pass were repaired and revalidated
on 2026-08-15:

1. `@loaders.gl/textures` is now development-only; the runtime imports
   `@loaders.gl/schema` directly. `npm audit --omit=dev --audit-level=high`
   reports zero vulnerabilities. The three unpatched `image-size` advisories
   remain isolated to the test-asset toolchain and are still reported by the
   full development audit.
2. The asset-script and lifecycle checkers now compare their own/Engine entry
   paths with Windows-safe absolute paths instead of POSIX suffixes.
   `asset-script:check` and `lifecycle:check` pass. The reconstructed Stage-8
   review is explicitly a source-contract tombstone, not measured evidence.
3. The Spine runtime now uses typed source JSON and timeline boundaries instead
   of explicit `any`. Its bone-timeline cache was extracted from the large
   orchestrator so `contracts:check`, `responsibilities:check`, Extensions
   typecheck, and all 156 Extensions tests pass.
4. The lifecycle checker again recognizes `Engine._acquireDevice()` as the
   single instrumented device acquisition path; the focused nine lifecycle
   tests pass.

Two additional source issues exposed by the broader rerun were also fixed:

- Animation Editor project cloning now uses its JSON-only project contract
  instead of the slower platform `structuredClone` hot path. The 10,000-key
  drag P95 dropped from repeated 46.78–59.93 ms results to 17.71–22.90 ms
  without changing the 50 ms budget; all 107 tests pass.
- The CPU benchmark suite now imports low-level glTF parsing from the existing
  experimental worker entry instead of assuming it is exported from the stable
  glTF facade. The CI benchmark profile executes to completion again.

After these repairs, `check:fast` reaches `observability:check` and stops only
because `review/baselines/render-pixels-stage7.json` is absent.

## Current Windows diagnostics (not formal evidence)

The current host is Windows 10 22H2 build 19045 with an NVIDIA Pascal adapter,
Chrome 151.0.7922.75, and Edge 151.0.4129.86. After the reviewed Windows support
change recorded by ADR 0072, the OS satisfies the release matrix. The host still
does not satisfy the reviewed Windows discrete-device enrollment contract:
Pascal is below the RTX 20-series/RX 6000-series release profile and no exact
adapter/browser/driver fingerprint has been enrolled.

- Chrome and Edge both pass the Scene Editor release lifecycle, native-3D
  Animation Editor, and Voxel Editor browser flows with native D3D11 WebGPU;
  observed owner residuals and GPU validation errors are zero.
- The combined Animation Editor designer flow is functionally successful but
  records 53–76 ms long tasks on this host, above the unchanged 50 ms candidate
  budget. This is retained as a diagnostic failure; the budget was not relaxed.
- The legacy Windows-discrete evidence validator starts correctly and identifies
  the three missing diagnostic artifacts: real renderer, planar reflection,
  and ambient occlusion. ADR 0073 no longer makes those fixed-profile artifacts
  the formal rendering-performance release decision.
- The non-enforcing CPU CI profile runs, but this host reports candidate ceiling
  overruns for PBR material preparation and device negotiation. These values are
  diagnostic only. The release comparison now uses a same-host five-engine full
  cohort and does not require the registered Apple CPU/GPU runner.

This section supersedes the earlier “still missing” list for local reconstruction

candidates and source-health evidence, not formal release promotion.

  pixel baselines were regenerated through their real Chrome/WebGPU generators.
  All normal comparison reruns pass.
