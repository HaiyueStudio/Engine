# GUI P2 implementation and verification

Problem: the P2 data/forms/content layer needed practical components on top of the existing editor, layout, virtual row and overlay owners.

Method: add 18 controllers across three focused extensions entries: gui-forms (Form, FormItem, InputNumber, AutoComplete), gui-data (Table, Pagination, TreeSelect, Cascader), and gui-content (Steps, Timeline, Descriptions, Rate, Result, Ribbon, ImagePreview, Carousel, Draggable, Resizable). They reuse P1 composition and the original input/focus, layout, modal, activity, renderer and collection owners. No root or Engine symbols were added.

Forms keep caller-owned data, cancellable validators and bounded active field bindings. Suggestions and lazy children reject stale requests. Table/Timeline use the original virtual list; TreeSelect uses the original tree and shared Popover. AutoComplete expands inline to keep one native text responder. Slots and image sources remain borrowed. Semantic defaults stay below application resources, named parts and explicit child styles.

The integration fixes belong to the existing owners: collection-admitted manual viewports and row containers enter the shared layout adapter, while private Tab/Collapse scroll flows keep their original path and scrolling is applied once. Native vertical text keys reuse the existing participant keyboard handler, including synchronous host-selection updates and IME/external-owner priority. Repeated Form unregister cycles release field controllers (32 retained before, 0 after); cleanup continues through a failing unsubscribe and rolls back reentrant disposal. Resize/Carousel keep the first pointer owner.

Conclusion: development implementation and automated validation passed for the frozen input 4542215fd1973772b64403290689be35c925fe02c566740d67e7e36aa90bb92e. The [completion receipt](../artifacts/gui-p2/20261127/completion.json) binds source, stage results, packages, native captures and preservation checks.

## Verification

- Root typecheck and all 115 fresh build targets passed.
- Full npm test: 2917 passed, 0 failed, 0 skipped.
- Four deterministic tarballs, 62 isolated installed consumers, 9 runtime categories and all public imports/declarations passed.
- 14 Windows native D3D11 WebGPU captures cover P1 and P2, dark/light themes, editing, selection, overlays, resize and 100,000-item recycling. All 168 static frames uploaded zero buffers; validation errors and owned-browser residue were zero.
- Architecture, API, docs, capability, package and existing budget policy gates passed. Source/config/runtime inputs stayed unchanged across the final validation stages.

This is development automation, not physical IME/gamepad/Mac/iPhone or formal production-performance qualification. Those remain tied to the later release candidate. Select search/multi and ColorPicker HSV/alpha were optional in the plan and are outside these 18 required components.
