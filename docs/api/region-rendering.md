# 区域渲染（0.2.2 开发候选）

`RenderView.createRegion(options)` 创建视图拥有的区域句柄，`Scene.addSystem` 的渲染选项或 experimental `RenderPipeline.add` 通过 `region` 使用该句柄。区域能力尚未完成发布资格；新增具名区域类型的包注册由 G13 统一处理，不应推断已发布 npm 包包含这些入口。

| 字段 | 语义 |
| --- | --- |
| `id` | 该视图内唯一的非空标识。 |
| `bounds` | `x/y/width/height` 为宿主逻辑像素，有限数值，尺寸非负。生产者使用区域本地坐标。 |
| `updateMode` | `demand` 失效后更新；`once` 请求一次；`continuous` 连续更新；`disabled` 不运行生产者。 |
| `clearMode` | `on-update` 每次更新清除；`once`／`never-after-initialization` 仅在新内容代次初始化时清除。待提交帧的兼容历史副本不重置内容代次。 |
| `visible` | 独立可见性门控。隐藏不消费待处理失效或单次请求。 |

句柄方法：`invalidate(reason)`、`setBounds(bounds)`、`setMode(mode)`、`setVisible(visible)`、`requestOnce()`、`dispose()`。`setMode('once')` 也产生新单次请求。成功提交后消费请求，取消不消费；新资源代次先初始化再采样。禁用区域若仍有有效缓存则继续合成该缓存；没有有效存储时初始化为透明且不运行生产者。直接重绘的新资源不能被视为保留了旧像素。

`once` 请求消费后，普通 `invalidate` 不会再触发该区域绘制；再次调用 `requestOnce()` 才更新。设备丢失后，新存储需要按当前生产者状态重建，即使旧单次请求已被消费；尚未消费的请求保留到新设备成功提交。`clearMode: 'once'` 的旧 GPU 累积像素随设备丢失，新存储从初始化后的内容开始。

句柄不可跨视图使用。销毁视图会释放其句柄，目标仍是借用资源；独立管线负责其 GPU 附件安全退役。缓存颜色上限为同设备 8 区域／64 MiB，普通工作集另计并纳入总资源验收，见 [ADR 0133](../for-ai/adr/0133-region-cache-working-set-accounting.md)。

外部录制上下文保留读取时的缓存版本；历史写帧复制录制时最近已提交的有效历史，包含 MSAA 各样本。尚未提交或已取消的帧不能作为后续帧的历史来源。提交顺序决定下一次录制可见的历史；需逐帧累积时先提交再录制。副本、裁切与安全退役共用原缓存上限，准入回退不承诺保存累积内容。

GUI 区域使用实际 backing 尺寸分别计算横纵缩放，允许 DPR 取整产生微小轴向差异。超出画面的部分被裁剪，本地内容不随可见范围缩放。目标物理尺寸或显示尺寸为零时不绘制，也不消费更新请求；恢复尺寸后重新组成完整输出。

父目标的颜色语义决定区域输出：显示目标执行曝光／色调映射并统一转换；浮点 RTT 保留 HDR 辐射值。完整场景缓存与 GUI 前景采用不同合成方式，以保持半透明背景的 RGBA。颜色语义切换使用新资源代次；父目标格式或描述符版本变化会重新合成输出。自定义目标通过已有 `getRenderPassDescriptorVersion(options)` 通知附件替换，宿主继续拥有目标及其退役责任。

区域 3D 分开使用原始投影尺寸、HDR 工作光栅和可见输出范围。工作光栅超过设备 `maxTextureDimension2D` 时，开发候选优先选择有界的工作窗口，使用二次幂相机／视口缩放保留原生光栅坐标；这可能保留可见部分前面的工作像素，完整 GPU 占用仍需计入。无法采用时使用保留相机比例的窗口投影。超限区域携带用户后处理链时仍明确报错，不能静默省略窗口外采样依赖，也不能据缓存准入失败推断任意尺寸都可直接重绘。辅助／时域后处理及完整组合资格见 G04 评审。

组合方式和可运行示例见 [固定 GUI 与连续 3D 指南](../engine-guide/region-rendering.md)。
