# 固定 GUI 与连续 3D 视图（0.2.2 开发候选）

在同一个窗口中，将工具侧栏设为按需更新，将 3D 视图设为连续更新。侧栏没有变化时复用已绘制的像素；交互、文字或资源变化时重绘整层。每次呈现仍组成完整画面，不能靠 scissor 保存上一次 canvas 纹理。

此能力仍在开发，区域调度使用显式 experimental 接入。查看已注册的 [region-rendering 示例](../../examples/region-rendering/main.ts)，通过 `npm run build:target -- example:region-rendering` 构建后打开其 `index.html`。示例使用公共包入口，展示侧栏交互、3D 曝光、暂停后全静止以及重新唤醒；DOM 中的计数不会反过来使 GUI 缓存失效。

```ts
const view = scene.renderView;
const sidebar = view.createRegion({
  id: 'sidebar', bounds: {x: 0, y: 0, width: 260, height: 720},
  updateMode: 'demand', clearMode: 'on-update', visible: true,
});
// gui 是使用该区域本地坐标和独立 roots 集合的 GuiSystem。
scene.addSystem(gui, {region: sidebar, pass: 'isolated'});
```

每个生产者都要注册到其拥有视图的区域；全局覆盖层也需要明确的拥有者。侧栏中的 GUI 坐标从区域左上角开始，`bounds` 使用宿主逻辑像素，resize 时按新的显示尺寸更新。使用独立 roots 集合，避免同一套 GUI 同时被多个系统绘制。

需要跨过侧栏与 3D 边界的 Popup、Modal、Toast，放在独立的整窗 GUI root 中，按最后一层合成。控件坐标使用宿主逻辑像素，Modal 的背景也覆盖整窗。下面的接入与侧栏共用一个视图，但各自持有 roots：

```ts
const overlayRoot = new GuiRoot();
const overlayRegion = view.createRegion({
  id: 'global-overlay',
  bounds: {x: 0, y: 0, width: engine.displayWidth, height: engine.displayHeight},
  updateMode: 'demand', clearMode: 'on-update', visible: true,
});
scene.add(new Entity('global-overlay').addComponent(overlayRoot));
scene.addSystem(new GuiSystem(engine, {roots: new Set([overlayRoot])}), {
  region: overlayRegion, pass: 'isolated', sort: 10001,
});
const modal = overlayRoot.add(new GuiModal({title: 'Settings'}));
modal.show();
```

这里的类来自现有公共 Engine／GUI 入口；区域装配仍是本指南开头标明的 experimental 接入。resize 时通过 `overlayRegion.setBounds(...)` 同步更新整窗逻辑范围。需要跨区的 Select 也由这个 root 拥有，其弹出列表使用同一宿主坐标；侧栏本地 root 内的控件仍受侧栏附件边界约束。

GUI 的 show／hide、文字、列表滚动、Toast 动画与移除会使覆盖层失效；`on-update` 清除整层再重画，关闭后下层内容从各自有效区域重新组成，不需要保存旧呈现纹理。空覆盖层初始化后可以保持静止，Toast 到期或从 root 移除后停止驱动它的动画。整窗覆盖层与其他区域共用缓存额度；准入失败时仍采用前述有序回退，并在诊断中报告。跨系统输入消费、Modal 焦点与捕获由 G05 的统一输入接入负责，当前示例装配不能代替这些资格。

宿主可通过 `invalidate(reason)` 标记程序内容变化，通过 `requestOnce()` 请求一次更新，通过 `setMode('continuous' | 'demand' | 'once' | 'disabled')` 更改调度。请求在成功提交后才被消费；隐藏期间保留失效。全部区域静止时渲染提交停止，业务模拟时钟由宿主决定，暂停画面不要求停止业务更新。

`once` 区域在请求消费后冻结已有像素，内容变化本身不会再绘制。设备恢复时按当前 GUI／场景状态重建新缓存，然后继续冻结；恢复期间的新单次请求不会丢失。仅首次清除的跨帧累积属于原 GPU 存储，设备丢失后从新存储的初始化内容重新开始。

缓存是有限资源。同设备共享的 8 区域／64 MiB 包含保留颜色、缓存 MSAA、resolve、裁切副本及退役重叠。正常整帧工作集及退役重叠单列，深度和其他资源仍计入总 GPU 占用。较大动态视图超出缓存限额时，物理上互不重叠的侧栏仍可保留缓存；透明交错或重叠无法安全混合时采用有序整视图重绘。直接重建的新存储不保证保留历史像素，不能用它实现跨帧累积效果。

区域中间目标采用线性存储。UNORM／sRGB 父目标中，3D 先处理曝光和色调映射，GUI 在线性空间合成，最终转换一次。浮点 RTT 保留场景 HDR 辐射值，与普通浮点捕获一致；显示曝光和色调映射不改变这类输出。具体格式、采样数和所需设备特性仍取决于宿主目标。

单独 GUI 的缓存保存前景，采用预乘透明叠加；已包含背景的完整场景位图按完整 RGBA 写回覆盖区域，避免半透明背景被再次混合。清除重置这项语义，加载保留它，取消帧保留已提交内容。自定义目标替换附件时应更新其描述符版本，保证静止画面也能重新合成；目标资源仍由宿主负责安全退役。

设备尺寸允许时，3D 裁剪保留原始相机比例和小数位置，在完整区域光栅上完成后处理，再取可见像素。因此 FXAA 等邻域处理不会提前丢失画面外的输入。直接裁剪路径的临时颜色副本每次完整复制，属于本帧工作数据；复制次数、字节与退役重叠需和完整 GPU 资源一起核对。

多个场景视图可以共享同一相机组件；绘制计划分别捕获投影、逆矩阵、视锥与抖动，提交或取消前保留各自的 CPU 快照。区域句柄仍只属于创建它的视图，不同父视图分别装配其区域管线，并共享同设备缓存总预算。记录某个区域时只消费该区域视图，不展开外层的其他场景视图。后处理参数和任意待提交 GUI／3D GPU 资源的组合资格以 G04 评审为准。

交替记录独立视图时，一次调用中未出现的视图不视为已移除；完整视图族则可以协调其成员集合。闲置相机快照采用有界复用，尺寸代次和不再复用的快照会释放对应的 uniform stream。已编码但尚未提交的命令仍保留其地址和缓冲代次，提交或取消后才允许复用；共享 arena 的容量属于完整 GPU 资源计量。

超出设备尺寸时，工作窗口优先保留原生光栅坐标，通过二次幂相机／视口缩放维持采样位置；只缩减超限轴，其他轴保留原来的分数视口。此策略受独立的分配策略约束，可能保留可见部分前面的工作像素；其额外颜色、深度与退役占用都需在完整 GPU 快照中核对，不计入保留像素缓存。无法采用时使用相机窗口投影。非空用户后处理链仍明确拒绝，需先解决窗口外邻域／时域采样依赖；具体像素资格以 G04 评审中的设备、材质与裁剪范围为准。

参数语义见 [区域 API](../api/region-rendering.md)。当前跨区覆盖层、复杂后处理组合、超大区域回退、清屏历史、多视图与完整设备恢复的资格以 [G04 评审](../../review/engine-0.2.2/README.md)为准；示例和诊断通过不代表正式设备性能或版本发布资格。

GUI 命令在具备提交／取消边界的录制上下文中保留其顶点、视口参数和自有图片／字体纹理。后续内容变化不会覆盖尚未提交帧的数据；正常顺序提交继续复用缓冲容量。移除节点、更换资源或销毁 GUI 时，旧资源等相关录制提交／取消及队列完成后再释放；设备丢失会废弃旧设备上无法提交的录制。借用的外部纹理仍由提供方保证有效期。

待提交帧读取的区域缓存也保留独立版本。外部上下文中的历史写入以录制时最近已提交的有效内容为起点，取消不会发布该版本；多个未提交写帧不按录制顺序自动串联。需要逐帧累积时，应先提交上一帧，再录制下一帧。MSAA 历史保留各个样本的颜色和 alpha，不能用 resolve 后的平均颜色替代。

这种隔离有成本：历史副本增加一个区域目标和一次整区域复制，MSAA 4× 使用私有逐样本复制 pass；旧版本及退役重叠仍受同一 64 MiB 上限约束。管线自动提交且没有其他待提交使用者时继续原地复用，静态 GUI 也不额外复制。准入不足时采用已声明的重建回退，跨帧累积不能依赖被回退丢弃的缓存。

已覆盖的 Basic 材质颜色／图片替换和对象表同样保留待提交版本。后续变化可能创建额外缓冲；正常顺序提交继续复用，第二个未变化视图不重复上传对象表。自有图片等相关录制结束后释放，借用纹理仍由调用方管理。其他材质、几何变形和完整设备恢复的资格以 G04 评审为准。
