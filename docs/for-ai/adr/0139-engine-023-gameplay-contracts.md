# ADR 0139：0.2.3 游戏流程与 GUI 组件合同

- 状态：接受，2026-10-31；用户要求制定 0.2.3、补充四类 GUI 能力并完成 G01。
- 范围：具名兼容增量的合同与版本准入。运行时仍为已发布 0.2.2；本决定不宣称实现、设备资格或发布完成。

## 问题

已有 Scene、物理世界、输入采样器、GUI、Tilemap 版本缓存及音频 owner 应继续复用。重复开发基础设施会制造生命周期和输入归属冲突；不明确公开子集则会把实验功能或私有实现一并暴露。现有默认键盘轴方向、物理校验和局部地图更新也有具名问题。

## 决定

1. [机器合同](../../../config/gameplay-023-contract.json)、[目标声明](../../../review/engine-0.2.3/api-contract.d.ts)和[行为矩阵](../../../review/engine-0.2.3/contract.md)共同冻结 G01。声明文件是待实现的评审合同，当前包声明仍为已发布 API 的权威来源。
2. 根入口保持原 30 个符号。14 个具名子路径合计增加 69 项导出（含原实验能力的具名提升），零空白储备。Engine `/gui` 106→107、`/physics` 42→45、`/physics/backend` 44→46、`/input` 3→10、新 `/audio` 7；extensions `/gui-layout` 11→12、`/tilemap` 8→10，以及七个 focused 新入口。准确名称以机器合同为准，原类型增量不另算新符号。只提升 InputActionMap 六项既有声明和 owner-safe mixer 五项既有声明；保留原实验入口与类身份，不批量提升实验聚合入口。
3. Engine、extensions、shader-language 目标 0.2.3；animation-spec 无格式或实现变更，保持 0.2.2。该具名兼容新增遵循 ADR 0132 的 patch 准入方式，不接受破坏变更。G11 在真实 tarball、声明、依赖闭包、示例和验证齐全后原子集成，G01 不修改包版本或正式 API 基线。新错误使用原 EngineError／EngineErrorCode，不增加错误框架；错误清单和文档锚点亦在机器合同内。
4. 场景流程拥有新创建的待提交 Scene，复用原 Scene.load 与 AssetManager；取消或失败销毁暂存场景，不修改旧 loadMany 的逐项 assign 语义。固定步进只抽私有共享时钟，不增加第二物理世界或角色时钟。角色使用既有运动学刚体、真实 box/circle 扫掠及原 tick。
5. Box2D 实际依赖为 box2d.ts@1.0.2。其 b2ShapeCast 未赋值 output.point，初始重叠可能返回零法线命中；必须使用距离 witness 重建普通接触点，并先用碰撞流形区分穿透与触碰。驱动能力和方法均为可选增量，旧后端不破坏；不支持时明确拒绝，不能用射线／AABB 近似冒充扫掠。
6. 长列表／树固定行高、稳定 key、有界可见窗口；与 HYA 只共享纯窗口计算。图集地图保持原颜色模式和静态版本命中，只更新脏块；保留 markDirty 全失效语义。音频重用原 mixer，保留 HYA 精确采样、宿主与解码所有权边界。
7. Tabs 增强现有 GuiTabContainer：逐页文字左／右图标、尺寸、间距。Breadcrumb、Badge、Collapse 放入 focused `@haiyue/extensions/gui-controls`，复用原 GuiContent、主题、布局、焦点、IME 和弹出层；不引入 antd、React 或新 GUI 类。保留借用内容与图像，展开、计数和导航状态不复制 owner。
8. 继承既有生产帧节奏、GPU 5%、画质、资源与具名 CPU 调查边界。冻结生产／压力／诊断规模、变更比例、冷启动和稳态，缓存仍为 8 区域／64 MiB，工作集与退役分别计量。包体按实际能力、重复实现审查及有限储备另做具名准入，不以文件数卡点。诊断基线不能推广正式性能资格。
9. 哈希复核仍服从 ADR 0126 等已接受范围；本合同仅规定验证输入，不授予任意运行时变更复用权限。0.2.2 的具名 SwiftShader 超时许可不延续。受影响真实设备由 G11 绑定新候选接收，设备缺失不能算通过。

## 验证与后续责任

唯一活动结论为 [0.2.3 验收入口](../../../review/engine-0.2.3/README.md)。G01 保存反例、真实后端试验、公开包回读、CPU／结构与原生 GPU 诊断，以及策略负例检查。后续 owner、具名 Native 消费路径与未实施项均在合同中；G02–G10 实现，G11 负责公开接线、设备、全局门禁及无发布演练。没有发布、推送、标签或旧基线推广授权。
