# ADR 0140：视觉小说与 HYA 舞台合同

状态为接受。适用于 Engine 0.2.4 的兼容增量与 G01 能力结论。公开入口由 G07 集成。

## 问题

剧情运行时持有分支与动作状态，HYA Player 持有动画与绘制，存档服务持有版本和存储。视觉小说需要统一装配这些能力。多个现有 Player 按注册顺序进入区域合成，较晚注册的替换角色会盖住原本应在上层的效果。原音频淡出会写入已配置音量。

## 决定

1. 作者台本编译成现有 NarrativeDefinition 和稳定 ID 关联的舞台数据。唯一分支执行器为 NarrativeRuntime。采用具名的独立入口，导出、逐包版本和错误映射见[机器合同](../../../config/visual-novel-024-contract.json)。
2. 每个素材实例用原 HYA Player。新镜头按画面层序注册并准备隐藏槽，等必需资源和首帧就绪后，在同次呈现前切换全部可见性。槽内变化复用现有时间与状态接口。按现有区域缓存约束分别记录活跃工作集和退役资源。
3. 同一帧来源推进各 Player。已到达的具名事件由舞台绑定到当前请求、实例及代次，重复或过时事件只保留在诊断中。简化装饰过渡仍提交与原流程一致的结束状态。
4. 存档绑定稳定行和舞台槽状态。兼容快照先在隐藏场景恢复，再静默 seek 并与剧情同时交接。浏览器缩略图采用已提交的 RGBA 帧，经现有 2D canvas 编码和 GameSaveService 写入。回看用隔离会话及明确的动作端口。
5. 菜单借用既有 GUI 模态焦点。行配音与回听持有独立音频租约。场景音乐的临时增益叠加到持久音量，并在取消或离场时释放。

## 验证与交接

已发布包的能力验证、失败反例、采样口径及后续设备责任在 [G01 检查索引](../../../review/engine-0.2.4/g01-checks.json)维护。G02 至 G06 按合同实现并集成示例。G07 负责真实输入、听音、候选性能及正式发布前门禁。
