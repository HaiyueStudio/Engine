# ADR 0125：G05 固定预热后连续采样

- 状态：接受；2026-10-13 用户明确批准连续采样。
- 合同：[lighting-continuous-021.json](../../../config/lighting-continuous-021.json)。
- 取代范围：ADR 0117 中新 G05 验收沿用逐次 120 秒冷却的要求。原协议、冻结预算和历史结果保留。

## 问题

房间、实例与 Forward 的 264 个原计划捕获仅冷却就需要 8.8 小时。长时间空闲反复改变低负载频率状态，不能代表持续游戏负载，也不保证采样期间频率稳定。历史 macOS 结果不能作为本机 Windows 的比较基线。

## 结论

本机 G05 使用固定预热后连续采样，取消捕获间的 120 秒等待。Chrome 和 Edge 均使用真实 NVIDIA 独显身份；继承冻结合同的独显数值预算，不把设备写成 AMD。该决定不删除场景、不放宽绝对预算、像素容差、内存上限或既有 G05 相对预算与稳定性检查。G09 的生产流畅度解释仍由 ADR 0124 单独拥有。

## 解决方法

1. 采样前登记完整顺序与输入哈希。全部房间负载、静态与动态、reference/tiled、1k/10k 实例、1/4 视图、四种实例变体及 Forward 1/8 灯保留。
2. 每浏览器三轮，每捕获固定 120 帧预热，CPU 与 GPU 各 300 个样本。使用共同 fixture、分离计时与逐帧完成方式；不裁慢样本、不择优重试，不将离屏 fence wall time 当成呈现帧率。
3. Forward 从原冻结 G01 修订构建独立来源快照，在同机、同浏览器按新协议采集基线和候选；不跨机器套用旧时间。基线和候选交替排序，保留两者全部三轮。
4. Windows 主机信息保留 CPU、显卡、驱动、电源方案和采样忙碌度，不伪造 `pmset` 或持续频率保证。跨轮波动仍按独立 G05 合同报告，不能因等待取消自动通过。
5. G09 顺序附件复用后，按实际物理纹理分配核算内存；逐视图像素完整性另行验证。对每个逻辑视图仍保守计入一套 G-buffer、对应 tile 和共享存储，原 64 MiB、四视图、两在途代次限制不变。
6. 原协议入口继续表达原合同；新入口和纯策略测试单独登记。脏工作区实测只提供本机证据；最终发布仍需要同一干净候选和其余发布门禁。
