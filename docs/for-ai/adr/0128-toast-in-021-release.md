# ADR 0128：Toast 纳入 0.2.1 发布

- 状态：接受；2026-10-16 用户明确要求，依赖该能力的游戏需要发布 App Store。
- 后续限定：[ADR 0129](0129-readback-repair-evidence-reuse.md) 允许本候选完成七组采样后，因独立 readback 夹具修复而严格复核固定六组；完整正确性重采，其他要求不变。
- 取代范围：[GUI ADR 0124](0124-gui-toast.md) 中“留到下一 minor、不作为 0.2.x patch”的版本安排，以及此前将 Toast 排除在 0.2.1 候选之外的范围决定。原文与旧候选证据保留。

## 问题

游戏的保存等操作需要通过现有引擎 GUI 显示短确认消息。将已实现的 Toast 推迟到下一 minor 会使该游戏无法使用计划中的 0.2.1 发布包。

## 决定

本次明确将 `GuiToast`、`GuiToastOptions` 纳入 `@haiyue/engine@0.2.1` 的稳定 `./gui` 子路径。沿用已评审的 GUI 86 个符号归属，根入口保持 30 个概念，其他包版本和预算不因本决定扩大。这是本次版本安排的具名调整，不变更其他能力的发布规则。

实现、借用图标所有权、毫秒计时、按需渲染、单帧推进、暂停取消、穿透点击和序列化语义继续遵循 GUI ADR 0124。游戏在实际保存成功后调用 `show()`；App Store 发布、系统权限、截图保存结果和平台分享仍由游戏及 Native 层负责。引擎不增加平台 SDK 或 Native 依赖。

## 验证与证据

公开包验证必须从真实 0.2.1 tarball 导入并运行 Toast，检查 `GuiToastOptions` 声明，并在 GUI 消费 bundle 中保留该导出；原包体上限不变。现有单元测试继续覆盖替换、空闲首帧、暂停、多视图、透明度和图标生命周期。

包含 Toast 的运行时与 `55feff1` 旧候选不同。[ADR 0126](0126-g05-stability-and-evidence-reuse.md) 的复用限制不放宽：旧七报告和原失败保持，只作为历史对照；新候选需取得自己的七类完整报告及全局发布资格。GUI 单元、包消费或游戏历史测试通过不能代替该资格，也不等同于 App Store 审核通过。

当前候选和剩余项统一见 [0.2.1 验收结论](../../../review/engine-0.2.1/README.md)及[候选清单](../../../review/engine-0.2.1/release-candidate.json)。
