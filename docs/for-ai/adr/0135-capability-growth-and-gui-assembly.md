# ADR 0135：按能力增长审查包体与 GUI 装配

- 状态：接受，2026-10-24；用户要求先补五个 HYA 独立消费者，再处理包体和 GUI 装配，并允许随功能增加适度放宽体积预算，重点检查重复功能代码。
- 部分取代：ADR 0122 中固定沿用旧字节上限的要求，以及 ADR 0134 对本轮预算集成阶段的限制。其他能力、API、设备、画质、资源和性能合同保持。

## 问题

0.2.2 新增组合格式、GUI 布局、输入、编辑、皮肤和拖放能力，旧版包体上限不能单独判断新增实现是否合理。反过来，新增功能也不能解释重复的布局器、采样器、编辑器或被误打入的重型后端。独立 GUI 入口与完整引擎的默认 GUI 场景装配有不同兼容责任。

## 决定

1. 五个 HYA 运行时入口均进入正式 packed consumer 矩阵，保留全部七个运行时工厂；实际 tarball 安装后验证公开声明、工厂调用、事务与释放。文本、布局、数据和音频消费者不能带入 GUI、3D、来源播放器或 OpenType；播放器保留真实绘制与 GUI，OpenType 仍在动态闭包。
2. 先核对能力归属、实现复用、打包身份和实际测量，再更新容量与有限增长储备。格式包 packed/unpacked 上限改为 190,000／750,000 B，GUI/font 改为 95,000 B gzip，narrative GUI 改为 23,000 B gzip。旧值、原失败和原样本保留；不按文件数卡点，不删除功能凑体积。
3. 新五个入口的总 gzip 容量依次为 player 500,000、text 20,000、layout 60,000、data 28,000、audio 21,000 B。player 初始／总分块上限为 380,000／500,000 B，OpenType 必须延迟。容量针对未压缩语法的正式 Rollup 消费口径，不能和库压缩文件或单独某个动态块混为一谈。
4. 词法克隆检测仅作辅助审查，不把“未发现长函数克隆”称为没有语义重复。必须追踪组合 owner 到原状态机、共享布局、原动画绘制、G06 编辑及唯一 GUI 输入域的依赖。格式验证与运行时资源校验属于不同信任边界，不因形似就合并或移除。
5. 场景渲染访问器只借用已存在的 owner，不依赖 Scene 构造。私有 `SceneRenderAccess` 保存原 WeakMap 关系，公开符号与同步语义不变；直接使用访问器和动态 GUI 的消费者不应提前装配 GUI／3D。
6. 保留主入口 `new HaiyueEngine()` 和同步 `createScene({gui:true})` 的默认行为，因此完整主入口仍包含 GUI 构造能力。`@haiyue/engine/gui` 作为独立入口共享同一套类型、资源和输入 owner；本轮不创建另一套 Engine／GUI 类、全局注册开关或依赖导入顺序的装配。完整主入口的 GUI 完全延迟不作为本轮通过声明；未来若提供显式按需场景工厂，应单独审查公共合同。

## 验证

正式包门禁使用隔离输出目录保存新报告和 tarball，旧失败不覆盖。检查五个 focused consumer、严格 TypeScript、ESM／Node、CLI、静态／动态闭包与最终制品哈希；场景生命周期和 GUI 分包回归验证同步兼容与共享身份。工作区类型、测试、构建及 API／架构／文档检查须通过。当前测量、重复实现审查及未完成设备资格集中在 [0.2.2 验收入口](../../../review/engine-0.2.2/README.md)。

本决策不授予 G11 完成、G12 性能或 G13 发布资格。
