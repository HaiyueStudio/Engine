- 后续具名例外：[ADR 0131](0131-framegraph-download-context-evidence-reuse.md) 单独批准下载检查的上下文绑定修复；本页决定和固定 PBR 字节保留。
- 调整范围：[ADR 0126](0126-g05-stability-and-evidence-reuse.md) 第 4 条的第二个具名例外；[ADR 0129](0129-readback-repair-evidence-reuse.md) 的原决定及固定 readback 修复字节保持。
- 执行入口：[PBR 页面策略](../../../scripts/pbr-example-pixel-policy.mjs)、[具名报告与修复哈希](../../../scripts/engine-021-evidence-policy.mjs)、[原始数据独立复核](../../../scripts/check-engine-021-evidence.mjs)。

## 问题

包含 Toast 与 readback 修复的干净候选 `1260d9b521b19c686794ad2f92056fe47662fb5a` 完成新的 224 项正确性，六组原始数据与重建字节复核通过。后续完整发布门禁在 PBR 示例整页截图停止：旧参考没有记录字体环境；当前 Windows 的等宽文字为 NSimSun，系统界面为 Microsoft YaHei UI，文字和控件布局与旧参考不同。六种材质模式的场景中心平均像素误差约 0.02，整页约 4.45。独立新配置重复截图的六种模式全部逐字节一致。

## 结论

Windows 使用具名的独立整页图像参考，旧参考原文件保留，其他既有平台继续使用旧参考。六种材质模式、全部 960×640 RGBA 通道、原平均绝对误差 2／通道差阈值 8／变化比例 2% 上限、控件交互、阴影与中性轮廓检查均保持。不得以裁剪界面、删减模式或放宽容差替代修复。此决定不晋升任何性能基线。

仅允许复核六份 `384ad34` 原报告和此次 `1260d9b` 的完整正确性报告；七份路径、SHA-256、各自采样提交及四份 PBR 修复文件的哈希在策略中固定。此次变更不触及运行时、七组采样器、测量配置或可执行工作负载。它不是其他截图、测试代码或后续修复的一般豁免。

## 解决方法

1. PBR 整页参考按平台显式选择。缺失、错误平台、模式缺项／增项、尺寸或 RGBA 数据损坏均失败；场景与面板明显变化仍必须被原像素预算拒绝。
2. Git 差异只允许固定四份 PBR 文件、原 ADR 0129 的固定三份 readback 文件（仅六组旧采样比较包含）、三个专项验收文件、候选策略及其测试、候选清单 JSON 与说明 Markdown。其他代码、依赖、配置或构建变化要求新采样。
3. 七组原始报告、截图、原失败和采样身份不改写。分别记录采样与验收提交；独立复核全部原始捕获、配置、主机、605 个正确性输入，并重建四个入口逐项比较 19 个可执行块。实际覆盖以机器审计为准，任何缺项或哈希变化继续阻断。
4. 完整全局门禁、独立包、无发布演练及其审计、最终正式光照证据检查仍须从冻结候选完整执行。专项复核或 PBR 单项通过不授予发布资格；不发布版本，不晋升性能基线。
