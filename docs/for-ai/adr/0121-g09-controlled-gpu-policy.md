# ADR 0121：G09 驱动与 Chrome GPU 电源条件

> 历史诊断协议：本记录将共同校准、开发基线和 5% 微基准回归作为 G09 准入前置条件的部分已由 [ADR 0124](0124-g09-production-performance-acceptance.md) 取代。实验协议与历史结果保留；当前验收从 [G09 结论](../../../review/engine-0.2.1/g09/README.md)进入。

状态：接受，开发机采样协议 v4；不代表性能或发布验收通过。
日期：2026-10-09。
接续 [ADR 0120](0120-g09-controlled-cpu-power.md)、[ADR 0118](0118-g09-cold-steady-sampling.md)。

## 问题与依据

相同八灯人口曾在不同 GPU 电源状态下产生不可比的跨轮计时。只有设置保存成功或单次 GPU 结束频率，不能证明运行中的共同稳态。独立诊断完成后，需把实际采用的驱动和应用设置纳入可复核条件，再执行全新校准与基线，不能把诊断直接提升为验收。诊断证据与限制见 [评审记录](../../../review/archive/README.md)。

## 决定

使用 g09-forward-cold-steady-v4。注册本机签名驱动 582.78；沿用 AC 供电、最低与最高处理器状态 100% 的临时方案，并对现有 Google Chrome 单应用配置设置“优先最高性能”。只允许该已存在的单应用条目，不改全局驱动设置。每次就绪观察及捕获前后回读该条目；丢失、继承、应用映射变化或数值变化均失败。校准与新基线使用同一 CPU 方案和相同 GPU 条件，冻结协议包含两者。

此项是驱动应用偏好，不是频率锁定，不保证 P0 或固定 MHz。正式计时仍使用未加入逐帧诊断记录的原生 fixture；GPU 定向诊断的频率观测不冒充正式人口的持续频率证明。不同驱动、不同配置或诊断人口不可拼成同机基线。

在任何计时开始之前等待 Codex、VS Code、Epic、Steam、任务管理器及非采样浏览器退出；启动器最多等待 5 分钟，不关闭用户程序。独立运行保留进程观察并核验指定后台程序未出现。Windows Search 的停用与恢复沿用已有实现，原本 Disabled/Stopped 时恢复为相同状态。

CPU/GPU 修改前写恢复日志，正常结束、采集失败和异常路径均恢复。恢复失败使运行失败；GPU 条目被外部改成其他值时拒绝覆盖，保留日志供处理。控制器通过 mock 故障检查和本机正常/故意中断恢复检查后，才能准备独立入口。

## 保持的口径

- 单灯与八灯两个案例，三轮 AB/BA/AB，共 4 项图像对照、12 项校准和 12 项全新基线。
- 每项正式计时前冷却 120 秒；入口连续三次 CPU 不高于 5%，主机负载门禁不变。
- CPU 校准每次保留全部 24000 帧，候选预热为 1200、3600、6000、12000、18000，以同一算法选择所有案例与变体共同满足的平台。
- 冷启动仍指新浏览器配置和设备、显式管线准备后的最初 120 个运行帧；场景与管线准备另报，不称为操作系统或驱动缓存冷启动。
- 基线保留全部 3000 个 CPU 样本、120 帧 GPU 预热及其后全部 300 个 GPU 样本。不能从诊断后段挑选更有利的窗口。
- CPU/GPU 回归上限仍为 5%；三轮 spread/CV 上限仍为 20%/10%，不删异常轮、不自动重试、不按速度选择预热。

v1/v2/v3 的合同副本和失败证据保留。v4 要重新完成图像对照与 CPU 校准，冻结条件后才开始全新基线。独立重算旧 v3 结果必须仍得到原失败与统计值。v4 通过也只形成当前继承 Forward 工作负载的开发机基线，完整 F0–F8、消融、G05/G07 与发布运行器资格仍分别验收。
