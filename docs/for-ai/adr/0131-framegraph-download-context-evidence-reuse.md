# ADR 0131：FrameGraph 下载上下文修复与七组限定复核

- 状态：接受；2026-10-18 用户明确批准此次限定复用七组。
- 调整范围：[ADR 0130](0130-pbr-windows-reference-evidence-reuse.md) 的具名例外增加一次独立下载检查修复；原 PBR／readback 修复字节、七份报告及所有预算保持。
- 执行入口：[下载上下文配置](../../../scripts/framegraph-example-download-policy.mjs)、[原生示例检查](../../../scripts/verify-framegraph-example.mjs)、[固定修复哈希与报告](../../../scripts/engine-021-evidence-policy.mjs)。

## 问题

冻结候选 `7bd14fa45093d24629114f016a039f3147bd8ad1` 的七组复核、冷启动／生命周期及完整慢检查命令通过，后续 FrameGraph 示例等待 JSON／PNG 文件时超时。共享运行器将页面放入独立浏览器上下文，而示例检查只给默认上下文设置下载目录。渲染、捕获像素及物理资源映射在超时前已通过；问题在检查入口的下载策略绑定。

## 结论

下载检查必须从当前页面取得非空的 `browserContextId`，只为该上下文设置具名输出目录。缺失页面／上下文身份或协议拒绝均失败，不能回落默认上下文或自动重试。单变量诊断确认 Chrome／Edge 共 18 项检查和四份真实文件导出通过；JSON 内容与冻结快照完全一致，PNG 宽度仍为 1200。原等待 60 秒上限、所有渲染／像素／裁剪／移动视口／销毁检查保持。

仅允许此次三份独立下载检查文件及具名验收／说明文件变化后，复核 ADR 0130 固定的相同七份报告。不涉及 Engine、示例实现、共享浏览器采样器、测量配置或可执行工作负载；原七组、原失败和原始文件均保留。其他修改继续按 ADR 0126 要求重新采样。

## 解决方法

1. 修复模块、原生检查入口和回归测试的 SHA-256 在策略中固定。继续逐字节核对原 PBR 四文件与 readback 三文件；旧决定不因此获得更宽的改码范围。
2. Git 差异、七份报告身份／哈希、全部测量输入、主机与配置仍必须独立核验。605 个正确性输入、四个新构建入口和 19 个可执行块逐项复核；诊断截图或摘要不能替代原始数据。
3. 候选仍须完整重跑全局门禁、正式性能比较、独立包、无发布演练及最终光照证据审计。CPU 报告式诊断的四项超线和缺少同比基线原样保留，不能冒充正式性能通过。本决定不改变任何预算，不发布版本，不晋升性能基线。
