# ADR 0136：先推进 G12，真实输入保留后补

- 状态：接受，2026-10-25；依据用户“暂缓真实输入验收，先完成 G12，后续补上验收”的授权。

## 问题与决定

G11 的运行时、公开包及自动化绘制已有具名证据，真实 IME、手柄及 iPhone 输入仍待人工设备验收。其等待不必阻止同一运行时的增量、素材、资源和性能工作。

1. G11 保持 `validating`，不写成完成；G12 改为 `active`。保留原依赖图，通过 milestone.json 的具名 executionAdmission 记录 G12 使用的 G11 交付与待验收边界。
2. 真实浏览器 IME、真实手柄及物理 iPhone 输入的补验顺序放到 G12 后，由 G13 集成清单显式追踪；补验仍阻止整版完成和发布。合成输入、自动化事件和测试端口不替代这些证据。
3. G12 可先完成代码、真实 tarball、授权素材、像素／语义对照、增量、长时资源、冷启动和具名性能验收。场景中的可重复输入仅用来驱动工作负载，不据此声称真实输入已通过。
4. Apple SDK 构建、PCM 输出、VoiceOver 与其他原有设备要求保持，不因本次输入顺序调整变为可选。G13 仍汇总全部平台资格；G12 完成不代表 G11 或整版完成。
5. 后补验收发现缺陷时，修复后核对源码、构建、配置、资产与制品哈希；受影响的 G12 正确性／资源／性能重测，不自动继承修复前资格。保持原失败、样本分母、资源／画质／性能门禁；字节容量仍按 ADR 0135 的具名规则审查。

## 验证与责任

机器状态与补验所有权见协调仓库 m23 的 milestone.json、G11／G12／G13 Goal 及 integration.md。当前证据集中在 [0.2.2 验收入口](../../../review/engine-0.2.2/README.md)，运行原里程碑检查、文档及依赖审计。该决定只调整执行顺序，不授予发布资格或授权实际发布。
