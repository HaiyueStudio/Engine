# ADR 0120：G09 共同处理器电源条件

- 状态：接受主机条件修订；尚未完成新条件下的完整性能验收。
- 日期：2026-10-07。
- 承接：[ADR 0118](0118-g09-cold-steady-sampling.md)、[ADR 0119](0119-g09-extended-calibration-horizon.md)。
- 配置：[v3](../../../config/framegraph-sampling-021.json)，历史 [v2](../../../config/framegraph-sampling-021-v2.json)。

## 依据

[独立诊断及三段电源对照](../../../review/engine-0.2.1/g09/cpu-record-diagnosis.md)在 Codex 退出后执行。旧版 A0 的慢窗口与处理器性能指标、固定算术探针同时变差；临时将原方案副本的交流最低处理器状态改为 100% 后，A0 后半段四个连续窗口的 CPU P95 为 0.500、0.495、0.495、0.495 ms。恢复原设置后，再现 0.755、0.510、1.020、0.555 ms 的窗口和算术探针变慢。

该有限对照支持将处理器电源条件固定为新的共同采样前提；不证明所有降频的底层原因，也不证明两场景、两版本、三轮正式人口已经稳定。历史在线对照仍有剩余波动，证据原样保留。最低状态 100% 不是锁定精确频率或 CPU 温度资格。

## 决策

v3 仅增加共同主机条件：交流供电、交流最低／最高处理器状态均为 100%。包装器复制原电源方案，仅修改副本的交流最低状态；原方案最高状态非 100% 时明确拒绝，不顺带调整其他设置。图像预检、完整校准及全新基线在同一个临时方案中执行，所有版本与场景共享条件。

每次就绪、捕获前后都记录并验证实际供电、方案身份及最低／最高状态；独立验证器拒绝缺失、不符或校准／基线跨方案的人口。按秒进程和约每两次观察的处理器性能计数器落盘，供失败诊断使用；连续计数器不是筛选帧或修正计时值的依据，也不能据前后观察声称捕获内每个瞬间都被验证。

成功、采集失败或服务恢复异常均进入外层电源还原流程：恢复原方案、核对原 AC/DC 最低／最高设置，再删除临时副本。还原或删除失败不得报告成功。独立启动器再读取实际系统状态确认。PowerCheck 仅验证这套电源生命周期，不产生性能样本；ServiceCheck 保持原来的纯服务检查语义。

v1/v2 配置与失败证据保留。新的 v3 必须在采样前固定，历史人口不可改名、拼接或晋升。以下规则全部不变：两个场景、A0/B4、AB–BA–AB 三轮、120 秒冷却、24000 帧校准、五个预热候选、两段完整 3000 帧窗口、原稳定性条件、CPU/GPU P95 **5% 回归预算**。仍先完整校准、冻结共同边界，再生成全新基线；失败不补采、不自动延长预热。

该条件只约束本机 inherited Forward 开发基线，不要求游戏终端启用此电源设置，不扩大为完整 F0–F8 或 G05/G07 clean release 资格。
