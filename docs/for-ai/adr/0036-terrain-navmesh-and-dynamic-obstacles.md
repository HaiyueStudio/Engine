# ADR 0036：地形 NavMesh 使用共享高度场与查询期代理净空

- 状态：Accepted
- 日期：2026-07-22

## 背景

RTS、点击移动和地面 AI 需要坡度过滤、不同角色体积、不可达目标回退及动态单位避障。为每种半径烘焙独立导航数据会放大内存和构建成本；把球体碰撞直接写入静态网格又会让移动单位造成高频重建。

## 决策

1. 导航能力从独立稳定子路径 `@haiyue/engine/navigation` 暴露，不进入核心生命周期入口；首版固定为 9 个公开符号预算，后续增长必须经过 API/ADR 评审。
2. 第一版采用 Y-up 单层高度场：从 Geometry3D 的 X/Z 投影中选择最高三角形，按三角形坡度生成静态 walkable mask。
3. 构建时计算静态边界净空；代理半径和最大台阶高度在查询时应用，使大小代理共享一份数据。
4. 动态球形障碍按稳定 id 存储，在 A* 与路径平滑时叠加；查询方显式忽略代理自己的 obstacle id。
5. 无法到达原目标时，查询返回起点连通区域内距离原目标最近的 partial 路径，而不是直接失败。
6. 路径结果使用可复用 TypedArray；寻路状态使用固定大小数组与 indexed binary heap，避免稳态查询产生逐节点对象。

## 边界

- NavMesh 负责全局通路和动态障碍占用，不替代移动阶段的连续碰撞检测或群体局部避让。
- 当前高度场不表示洞穴、叠层桥梁或任意重力方向。后续以新的分层 polygon backend 扩展统一查询接口，不在单层 cell 中塞入多高度数组。
- Geometry3D 顶点在构建前应转换到统一世界坐标；运行时移动地形需要显式重建或未来的 tile 增量更新协议。

## 验证

- 单元测试覆盖坡度过滤、大小代理窄通道、动态障碍、自身障碍忽略和 partial 目标。
- `examples/navmesh-rts` 覆盖真实 WebGPU 地形、RTS 点击、大/小球、陡坡和球体阻挡。
