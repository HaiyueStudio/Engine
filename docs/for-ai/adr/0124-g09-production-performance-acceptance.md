# ADR 0124：G09 以生产场景流畅度验收

- 状态：接受；2026-10-12 用户明确批准此方向。实施合同已调整，生产场景资格尚未取得。
- 合同：[framegraph-acceptance-021.json](../../../config/framegraph-acceptance-021.json)。
- 取代范围：ADR 0118–0121 中将共同校准、开发基线及 5% 微基准回归作为 G09 必经前置条件的决定。原实验协议、硬件范围和历史结果不改写。

## 问题

单灯 GPU pass sum 约从 0.145408 ms 变为 0.180192 ms，绝对差仅 0.034784 ms，却因三轮稳定性阻止了后续验收。差异不是完整帧耗时，也没有证明用户可感知卡顿。继续追求低负载微基准完全稳定的投入已超过其发布决策价值。另有高重叠负载达到数十毫秒的历史结果，不能把这些实际成本一并解释为设备噪声。

## 结论

G09 的硬性验收围绕正确性、代表场景流畅度、持续资源稳定和优化收益。相对变化 5% 保留为调查触发线，不能单独否决发布。跨轮不稳定或环境污染记为 `inconclusive`；未登记场景口径或缺少证据记为 `incomplete`；损坏、缺失或身份不符的证据仍无效。以上状态均不等于通过。

这次修改仅适用于 G09 及其交给 G05/G07 的验收要求。其他既有绝对预算、包/API、跨引擎竞争合同仍由各自政策拥有；不能借此取消真实的多灯绝对性能失败。

## 解决方法

1. **先登记生产口径，再采样。** 固定设备与浏览器、分辨率、画质、负载、目标 FPS、完整帧 P95/P99、长帧阈值/比例/连续数量、运行时长和冷启动/稳态边界。保留生产 F0–F5 与代表性 F8；压力极限不自动宣称普通场景帧率。现有 Mac 目标不能直接作为 Windows 已验证承诺。
2. **用实际呈现场景的完整帧节奏判断流畅度。** 平均 FPS、headless 吞吐、GPU pass 合计和带逐帧 fence 的 wall time 都不能独自替代它。CPU、GPU、等待、读回、分配分别报告。新指标的生产者、原始证据验证和发布接线必须齐备后，才允许宣告该项通过；当前尚未完成这部分生产场景资格。
3. **有界复核退化。** 预登记一轮配对比较，必要时增加一轮完整确认；共最多两次计划尝试。保留全部轮次和慢帧。超过 5% 时同时审查绝对毫秒、配对不确定性、能否复现和对生产目标的影响。仍无法解释则保留证据不足，不循环重跑直到绿色。不新增通用的绝对毫秒豁免线。
4. **持续问题仍阻断。** 渲染错误、崩溃、资源泄漏、设备丢失处理失败、持续卡顿，以及可复现且影响已登记目标的退化，必须处理。G09 还需至少一项可归因的生产收益，不能仅凭“看起来流畅”宣称优化完成。
5. **旧协议作为可选定位工具。** v1–v5、连续 GPU 观察、管理员电源控制、旧基线及其退出码继续表达原实验判定；不再是新验收的依赖。采样器新增独立的当前解释，不覆盖原 `status`。此次未重建或晋升任何基线，未更改原始样本。
