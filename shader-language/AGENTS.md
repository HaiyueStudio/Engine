# Shader Language instructions

## Architectural contract

- Typed Shader IR is the single semantic representation. TypeScript DSL, Material Graph, and future frontends lower into it; backends do not invent separate material or pass semantics.
- This is a build-time workspace. Only reviewed package exports such as `./material-graph` are public; the compiler
  must not enter engine runtime bundles or ordinary Editor startup bundles.
- WGSL is the production backend. GLSL ES 300 remains a bounded feasibility backend and does not imply WebGL2 renderer support.
- Graph JSON is untrusted data: no embedded WGSL, GLSL, or JavaScript. Reject unknown fields/capabilities precisely instead of ignoring them.
- The compiler describes shader resources and reflection; it does not allocate textures, schedule RenderGraph passes, or own GPU resource lifecycle.

## Changes and generated artifacts

- Treat `stage*-contract.json`, schemas, family JSON inputs, `migration-manifest.json`, and accepted ADRs as machine-readable contracts. A semantic or format break needs an explicit version/error path and usually a new ADR rather than rewriting history.
- Production family changes are atomic across all affected passes. Preserve deformation ordering, history ABI, binding ownership, varying/interface parity, and artifact hashes.
- Never edit generated WGSL/artifact files under `engine`, `extensions`, or examples by hand. Update compiler/family sources and run the appropriate generator.
- Constant folding, CSE, DCE, cache keys, and source deduplication must preserve provenance/reflection and deterministic output.
- New static variants require a declared capability/layout reason. Record and budget IR nodes, generated bytes, variant count, pipeline count, and compile/cache behavior.
- Do not change statistics or exclusion rules to make a cost gate green.

## Validation

```bash
npm run typecheck -w ./shader-language
npm test -w ./shader-language
npm run shader-language:check
npm run verify:shader-language-stage14
```

- Run the focused generator without `--write` first when checking staleness. Use the write form only after source changes are intentional, then inspect every generated diff.
- Showcase/material changes also run the Shader Language Lab and character-material verifiers.
